Some waits only your app knows about: it is searching the docs, uploading a file, holding a
place in a queue. `<aparte-chat-status>` says so in one quiet line. It is yours to turn on with
`visible` and off again; core never shows it by itself.

It is not the indicator for the pause before the first word of a reply: the reply's own
[waiting indicator](/components/waiting-indicator/) covers that, and showing both is two
indicators for one wait. The framework wrappers render one inside the transcript, driven by
their `isTyping` prop.

## Variants

### Without text

<Variant id="status-line-dots" />

Without `text`, the line is a single pulsing dot.

## Customize

| Variable | What it sets |
| --- | --- |
| `--aparte-status-color` | The colour of the text and the dot. |
| `--aparte-status-font-size` | The size of the text. |
| `--aparte-status-dot-size` | The dot's diameter. |

To draw the line yourself, `aparteGlobalConfig.setStatusRenderer()` replaces its contents; the
element keeps showing and hiding it, and keeps its accessible name.

## Accessibility

- The line is a polite live region: what it says is announced when it appears, without
  interrupting.
- With `text`, that text is what is announced; without it, the locale's `typing` word ("Typing"
  in English) is, from a visually hidden label.
- The dot stops pulsing under `prefers-reduced-motion`.
