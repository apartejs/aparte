`<aparte-model-selector>` lists the providers your config knows, one group per provider, with
the models each one fetches. A provider with no list to fetch shows the models it was given (the
Vercel AI SDK bridge's `models` option), and one given none is left out. With a single provider it
is a flat list. With `persist`, the choice is what the
next message is sent to: the pick is written into the config. Without it, the element only sends
`aparte-model-change`, for code of yours to act on.

It is built on core's [select](/components/select/), and it reads the config of the chat it sits in,
so two chats on one page each list their own models.

## Usage

```bash
npm install @aparte/plugin-model-selector @aparte/core
```

```ts
import '@aparte/plugin-model-selector'; // registers the element
```

Its place is the composer's toolbar. `margin-inline-start: auto` pushes it to the end of the
row; the four framework wrappers take it through their `toolbar` slot (see
[the composer toolbar](/guides/customization/composer-toolbar/)).

```html
<aparte-composer-toolbar>
  <aparte-model-selector auto-select persist searchable style="margin-inline-start: auto"></aparte-model-selector>
</aparte-composer-toolbar>
```

`details` adds a line under each model's name with what its provider declares: its
`description` and its `contextWindow` ("Long documents · 128K context"). The trigger keeps the
name alone, and the filter searches the line too.

The plugin exports `modelSelectorElement`, its element's spec, and every framework binds it as it
binds [any plugin's element](/frameworks/elements/#your-own-element-or-a-plugins):

## Customize

The list loads asynchronously, so for a moment the chat can be mounted with no model chosen.
To keep the composer from sending until one is:

```ts
import { aparteGlobalConfig } from '@aparte/core';

aparteGlobalConfig.setRequireModelSelection(true);
```

The composer greys out and comes back once a pick reaches the config: `auto-select` or the
reader's choice, on a selector with `persist`.

### Models a server runs

A chat whose turns run on a server ([the server loop](/guides/server-loop/)) or in an agent of its
own registers no provider, so the selector has nothing to list. The models still exist: the server
knows them and runs the one chosen. `createModelCatalogue` registers them as a provider that lists
them and runs none:

```ts
import { aparteGlobalConfig, createModelCatalogue } from '@aparte/core';

aparteGlobalConfig.registerAIProvider(createModelCatalogue({
  id: 'server',
  name: 'Our models',
  models: [
    { id: 'qwen3-32b', name: 'Qwen3 32B' },
    { id: 'gemma-3-27b', name: 'Gemma 3 27B' },
  ],
}));
```

The selector lists them like any provider's, the model selected goes out on every request as
before, and its capabilities gate what it cannot do. Nothing in a catalogue answers a turn: a page
with no stream runner that sends anyway gets an error that says so.

### Ask before switching

Without `persist`, a pick is only announced, so your app can say what switching costs before it
happens (a model to load, a conversation to cut) and put the old model back when the person
cancels. `picked` tells the two apart: `true` for the person's pick, `false` for the change your
own `setSelection()` makes, and for `auto-select`. Hand the event's detail and the element to a
function like this one, bound as each framework binds `aparte-model-change` in the tabs above:

```ts
import { aparteGlobalConfig } from '@aparte/core';
import type { AparteModelChangeEventDetail } from '@aparte/core';

declare function askToSwitch(modelId: string): Promise<boolean>; // your dialog

export async function confirmSwitch(
  detail: AparteModelChangeEventDetail,
  selector: { setSelection(providerId: string, modelId: string): void },
): Promise<void> {
  const { picked, providerId, modelId, previousProviderId, previousModelId } = detail;
  if (!picked) return; // our own revert, below
  if (await askToSwitch(modelId)) {
    aparteGlobalConfig.setModelConfig({ defaultProvider: providerId, defaultModel: modelId });
  } else if (previousProviderId && previousModelId) {
    selector.setSelection(previousProviderId, previousModelId);
  }
}
```

## Accessibility

- The button is named by its placeholder and the current model, and opens a list box;
  `searchable` adds a filter field.
- Providers are option groups, so a screen reader names the provider of each model.
