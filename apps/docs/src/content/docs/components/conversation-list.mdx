<Variant id="conversation-list" />

`<aparte-conversation-list>` draws the rows; it is not a store. You assign the `conversations`
property and set `active-id`, it renders them and tells you what the reader picked. As soon as an
item carries `updatedAt`, the rows are grouped by date: Pinned, Today, Yesterday, Previous 7 days,
Previous 30 days, then one heading per month. `flat` keeps your order with no headings.

Each row is two buttons: its title, which selects it, and a `⋯` that opens its menu.

## Variants

### The row's menu

Press `⋯` on a row above: rename, pin or unpin, archive or unarchive, delete. A right click on a
row, Shift+F10 or the Menu key opens the same menu there. Every item fires an
event and stops. Rename turns the title into a field (Enter or leaving it commits, Escape cancels); delete asks first,
inside the menu, because it is the one action you cannot undo.

### While a conversation answers

<Variant id="conversation-list-status" />

A row says what its conversation is doing. `running`: an AI is answering in it, and its title
[shimmers](/components/shimmer/). `waiting`: its turn waits for the person, a server run paused
on a question or an approval, and a mark sits beside the title. A screen reader hears the state
with the title ("Answering", "Waiting for you", in the reader's language).

With a [conversation controller](/guides/conversation-persistence/) you write nothing: it sends
`aparte-conversation-status` on `window` as each turn starts (`running`), pauses on the page
(`waiting`), resumes (`running`) and ends (`null`), from the turn's own `aparte-message-start`,
`-paused`, `-resumed`, `-done`, `-error` and `-aborted`. Without one, say it yourself, from the
same events:

```js
const list = document.querySelector('aparte-conversation-list');
list.setConversationStatus('c1', 'running');
list.setConversationStatus('c1', null);   // neither
```

`running` is always the conversation on screen: opening another one stops the turn. `waiting` is
the one state a conversation keeps once the person has gone elsewhere, because a paused run
survives the switch. After a reload, a paused conversation shows it again once it is opened and
its question is put again.

A state is about a conversation, not about one list: it is kept for the page, every list draws
it, and a list that appears later (a drawer opened on demand, a remount) draws it too. It is
keyed by conversation id, so two chats on one page whose ids collide share their states.

The state is data on the row (`data-status`) and the look is CSS, so it is yours to change. The
mark (`.aparte-conv-item__status`) is an empty slot until a state draws it. A dot for `running`
instead of the shimmer:

```css
.aparte-conv-item[data-status="running"] .aparte-conv-item__title {
  animation: none;
  background-image: none;
  -webkit-text-fill-color: currentColor;
  color: inherit;
}
.aparte-conv-item[data-status="running"] .aparte-conv-item__status {
  display: block;
  background: var(--aparte-success);
}
```

### Your own groups

An item can carry its own `group`, `{ key, label }`: a project, a folder, a workspace. A row that has
one is listed under that heading instead of its date or the Pinned group, the groups come first in
the order they first appear, and the items without one fall to the date groups below. `flat` still
draws no heading, and the search hides a group once none of its rows match.

```js
list.conversations = [
  { id: 'c1', title: 'Launch plan', group: { key: 'p-launch', label: 'Launch' } },
  { id: 'c2', title: 'Pricing', group: { key: 'p-launch', label: 'Launch' } },
  { id: 'c3', title: 'A quick question', updatedAt: Date.now() },
];
```

### Marks of your own on a row

`renderMeta` draws something of yours after a row's title — a shared mark, a count, a status — and
returns `null` for a row with nothing to say. An element goes in as it is; a string is text, never
markup. It sits beside the title button, not inside it, so a button or a link in it keeps its own
accessible name and its own tab stop.

```js
const list = document.querySelector('aparte-conversation-list');
list.renderMeta = (item) => {
  if (!item.shared) return null;
  const mark = document.createElement('span');
  mark.className = 'aparte-badge';
  mark.textContent = 'Shared';
  return mark;
};
```

Setting it draws the rows again, and it is read on every render after that. `renderMeta` is a
property, like `conversations`; its look is `.aparte-conv-item__meta`.

### While it loads

<Variant id="conversation-list-loading" />

`loading` shows skeleton rows until your store answers: a list that is not there yet is not an
empty list. An empty list draws nothing.

## Usage

<Usage />

The events carry the conversation's id (and the new title, for a rename); the array stays as it
was until you assign it again. To have the list carry out the menu's actions itself, register a
conversation manager with `setConversationManager()` and set `manage`: renaming, pinning,
archiving and deleting then happen on that manager, and `preventDefault()` on the event still
takes the gesture back. `manage` does not select: a click sends `aparte-conversation-select`, which
a chat bound to the manager answers by opening that conversation.

On a page with more than one chat, or when the chat has a configuration of its own, say which
chat the list drives. A click then opens the conversation in that chat alone, and `manage` acts
on that chat's manager:

```html
<aparte-conversation-list target="support-chat" manage></aparte-conversation-list>
<aparte-chat id="support-chat"></aparte-chat>
```

The rows come from the array, so the element takes no children: put the new-chat button and the
search field around it, in the [sidebar](/components/sidebar/).

### In React

`<AparteConversationList>` is this element as a React component: `conversations` is a prop, the
attributes are props by the names above, and each event is an `onXxx` callback — no ref, no
effect, and the same under React 18 and 19. Bound to `useConversationManager()`, the list needs
the manager's rows and its active id, and `manage` has the manager carry out the menu's gestures:

```tsx
import { useEffect } from 'react';
import { AparteChat, AparteConversationList, useConversationManager } from '@aparte/react';
import { createIdbStorage } from '@aparte/plugin-storage-idb';

export function ChatWithHistory() {
  const manager = useConversationManager();
  useEffect(() => { void manager.init(createIdbStorage()); }, []);

  return (
    <div style={{ display: 'flex', height: '100dvh' }}>
      <AparteConversationList
        conversations={manager.activeConversations}
        active-id={manager.activeId}
        manage
      />
      <AparteChat />
    </div>
  );
}
```

A click on a row needs no code: the chat bound to the manager hears it and opens that
conversation, and `manager.activeId` follows. To do a gesture yourself — ask before deleting, say —
leave `manage` out and take the callbacks, each called with the event's detail and then the event.
With `manage` on, `event.preventDefault()` in a callback takes that one gesture back from it.

The callbacks, without `manage`:

{/* doc-check: skip excerpt — a fragment of your component */}
```tsx
<AparteConversationList
  conversations={manager.activeConversations}
  active-id={manager.activeId}
  onConversationSelect={() => setDrawerOpen(false)}
  onConversationRename={(detail) => void manager.updateTitle(detail.id, detail.title)}
  onConversationPin={(detail) => void manager.pin(detail.id)}
  onConversationUnpin={(detail) => void manager.unpin(detail.id)}
  onConversationArchive={(detail) => void manager.archive(detail.id)}
  onConversationUnarchive={(detail) => void manager.unarchive(detail.id)}
  onConversationDelete={(detail) => void manager.delete(detail.id)}
/>
```

`conversations` is written when the array is a new one, and `activeConversations` is the same array
until the manager changes: pass that one, or a `useMemo` of your own, and not an array built in the
render, which would draw every row again each time. `active-id` takes the hook's `string | null` as
it is.

## Accessibility

- The list is a navigation landmark named from the `conversationList` locale key ("Conversations"),
  unless you give it an `aria-label` or `aria-labelledby` of your own.
- Each date group is a group named by its heading; the selected row is marked `aria-current`.
- The `⋯` button announces a menu and whether it is open; the menu's items are menu items, with
  the [menu](/components/menu/)'s keyboard: the arrows, Home and End, a letter to jump, and Escape
  back to the button.
- While loading, the list is `aria-busy` and a status line says the conversations are loading.
