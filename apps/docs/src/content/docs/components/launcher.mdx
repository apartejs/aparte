`<aparte-launcher>` is the support widget a product site puts at the bottom of every page, as an
element. A round button floats at the bottom of the window, on the inline-end side; a click opens
the chat above it as a card, under a header with a title and a ✕. A second click, Escape or the ✕
closes it.

Its content is yours: an `<aparte-chat>`, or your own card around one. The element shows it only
while it is open, so a closed launcher keeps the chat mounted — the conversation and the client
stay — but out of sight, out of the tab order and out of the accessibility tree. It stores
nothing: `aparte-launcher-toggle` fires on every change, for you to remember the state.

```html
<aparte-launcher label="Help" heading="Kilnhouse support" subheading="Usually answers in a minute">
  <aparte-chat></aparte-chat>
</aparte-launcher>

<script type="module">
  import { AparteClient } from '@aparte/core';

  new AparteClient().start(); // the chat inside answers like any other
</script>
```

## The header

The launcher draws a header over the card: the assistant's avatar, a title, a line under it, and
a ✕ that closes the chat. `heading` sets the title — unset, it is the button's `label`, else the
locale's `launcherHeading`, "Chat" — and `subheading` the line under it, for who answers and how
fast. Set `heading=""` for a header with no title, only its buttons.

The avatar is the assistant's, drawn by the avatar provider your messages use
(`setAvatarProvider`, a component of your framework included), in the assistant's avatar colours;
a picture set with `--aparte-avatar-image-assistant` shows there too. Without either, the header
shows none. The provider is called with a host that is not inside a message, so a provider that
looks for the message around its host should not assume one.

`header="false"` takes the header away, and the button in the corner closes the chat again. A
card that brings a header of its own keeps it and gets no second one: see
[Your own card](#your-own-card).

### Its colours

It wears the [Header](/components/header/) recipe, with your page's surface and ink.
To put it in your brand's colours, set a `background` and a `color` on it. Its title, the line
under it and its buttons take that ink, so one rule repaints the whole header:

```css
aparte-launcher .aparte-launcher__header {
  background: #1d6fe0;
  border-color: #1d6fe0;
  color: #fff;
}
```

## Maximize

`maximizable` adds a button to the header, beside its ✕, that makes the open chat fill the window
and brings the card back. Maximized, it is the sheet a phone gets, on any screen: the header on
top, the conversation at its reading width under it, Tab kept inside. It fades in at its new size
unless the reader asked for less motion. Escape brings the card back, and a second Escape closes
the chat. The button's name says what it will do: "Expand the chat", then
"Shrink the chat", the locale's `launcherMaximize` and `launcherRestore`.

```html
<aparte-launcher label="Help" heading="Kilnhouse support" maximizable>
  <aparte-chat></aparte-chat>
</aparte-launcher>
```

### Beside the page

The whole window suits an app, an admin, a tool someone works in. A site whose visitors read the
answer while looking at the page — "where is the Refund button?" — keeps the page in view with
`maximizable="panel"`: maximized, the chat runs the window's height along its inline end (the
right edge, on a left-to-right page), `--aparte-launcher-panel-width` wide (36rem), and the page stays in view and in reach
beside it.

```html
<aparte-launcher label="Help" heading="Kilnhouse support" maximizable="panel">
  <aparte-chat></aparte-chat>
</aparte-launcher>
```

### Its state

The state is `maximized`: an attribute the element reflects, and a property. From a script,
`maximize()` and `restore()` do what `show()` and `close()` do for `open`; in the markup,
`maximized` starts it maximized. `aparte-launcher-toggle` reports it with the rest of the state,
so a page can save the two together:

```ts
const launcher = document.querySelector('aparte-launcher');

launcher?.addEventListener('aparte-launcher-toggle', (event) => {
  sessionStorage.setItem('help', JSON.stringify({ open: event.detail.open, maximized: event.detail.maximized }));
});
const saved = JSON.parse(sessionStorage.getItem('help') ?? '{}');
if (launcher && saved.maximized) launcher.maximized = true;
if (launcher && saved.open) launcher.show();
```

On a phone the open chat already fills the window, so there is nothing to enlarge: the sheet hides
every maximize control, the header's and yours.

## Variants

### As a sheet on a phone

<Variant id="launcher-sheet" />

Under `breakpoint` (30rem of window by default, in width or in height — a phone held sideways too — or `none` for a card at any size), the open chat
fills the window under its header, Tab stays inside it, and the ✕ in the header closes it. Without
a header, the button moves to the top corner to close it. The element carries `data-sheet` while
the window is that narrow.

## Your own card

A card with its own header — a status, a menu, people who join — goes in as one child. The
launcher draws no header over a card that brings one: a `<header>` at the card's top level. A
header written another way needs `header="false"`. Mark your ✕ `data-aparte-launcher-close` and it closes
the launcher with no script; mark a button `data-aparte-launcher-maximize` and it enlarges the card
and brings it back, and the launcher keeps that button's `aria-pressed` in step with the state.
Inside a message's content both attributes are ignored.

```html
<aparte-launcher label="Help">
  <section class="help-card">
    <header>
      <strong>Kilnhouse support</strong>
      <button class="aparte-btn aparte-btn--icon aparte-btn--ghost" type="button"
              aria-label="Maximize the help chat" data-aparte-launcher-maximize>
        <aparte-icon name="maximize"></aparte-icon>
      </button>
      <button class="aparte-btn aparte-btn--icon aparte-btn--ghost" type="button"
              aria-label="Close the help chat" data-aparte-launcher-close>
        <aparte-icon name="close"></aparte-icon>
      </button>
    </header>
    <aparte-chat></aparte-chat>
  </section>
</aparte-launcher>

<style>
  .help-card { display: flex; flex-direction: column }
  .help-card header { display: flex; align-items: center; gap: 0.25rem; padding: 0.5rem 0.5rem 0.5rem 1rem }
  .help-card strong { flex: 1 }
  .help-card aparte-chat { flex: 1; min-height: 0 }
</style>
```

The launcher sizes its child; a card that stacks a header over the chat lays itself out as a
column and lets the chat take the rest, which is what the last rule does. Your button keeps the
name you gave it, so give it one that holds in both states, and let its `aria-pressed` say which:
`aparte-launcher[maximized]` is there for a glyph that changes with it.

## Usage

<Usage />

`label` puts text beside the bubble, and the button reads as a pill; without it the button is
round and named by the locale (`launcherOpen` and `launcherClose`). Open, it turns into a close
control, as a launcher does on every site; its two icons are yours to choose (below), the same
one twice for a button that keeps its bubble. The locale and the icons are those of the chat inside when it carries its own
config — the `config` a wrapper takes, or `attachConfig(chat, config)` — and the page's otherwise,
so a French chat gets a French button and header without a global setting. `open` opens it from
the markup or from a script, and `show()`, `close()` and `toggle()` do the same.

## Server rendering

The launcher draws its button and its header when it connects. On a server-rendered page that is
as soon as `@aparte/core` loads — before your framework hydrates — and hydration then removes what
it did not render. The chat inside already holds itself back until its framework has the page,
but that does not hold the launcher around it. Hold the launcher too: an element of yours that
carries `defer-hydration` in the server's HTML, and the release once the framework has
hydrated.

```html
<div id="help" defer-hydration>
  <aparte-launcher label="Help">
    <aparte-chat></aparte-chat>
  </aparte-launcher>
</div>
```

```ts
import { releaseDeferredHydration } from '@aparte/core';

// From your framework's mounted hook (useEffect, onMounted, onMount, ngAfterViewInit),
// once the page has hydrated:
releaseDeferredHydration(document.getElementById('help'));
```

Render `defer-hydration` on that element in the server render and in the hydration render
alike, so the framework finds the markup it sent. Until the release the launcher draws nothing;
once it is released it draws its button and its header, and the chat inside wakes with it.
[Hydration](/frameworks/elements/#hydration) says how the release works.

If something removes the button or the header anyway — a page that skips the release — the
launcher puts them back, so the chat stays reachable; the framework still reports the mismatch,
which holding the launcher avoids.

## Customize

| Variable | What it sets |
| --- | --- |
| `--aparte-launcher-width` | The open card's width (23.75rem), never wider than the window. |
| `--aparte-launcher-height` | The open card's height, header included (37.5rem), shortened to fit a short window. |
| `--aparte-launcher-panel-width` | The maximized chat's width with `maximizable="panel"` (36rem), never wider than the window. |
| `--aparte-launcher-header-height` | The header's least height (3.5rem), enough for a title and the line under it. It grows with what it holds, and the card under it gives up that room. |
| `--aparte-launcher-offset` | How far the button and the card sit from the window's edges (1.25rem). |
| `--aparte-launcher-gap` | The space between the open card and the button. |
| `--aparte-launcher-radius` | The open card's corners. |

The button wears the [button recipe](/components/button/) — solid, primary, large — and the
launcher sits at `--aparte-z-dropdown`, above the page and below what you raise over it.

Its two icons have names of their own, so you can redraw the button without redrawing every
close button in the chat: `launcherOpen` (the bubble) and `launcherClose`. Without them it draws
`messageSquare` and `close`. The header's buttons draw `maximize`, `minimize` and `close`.

```ts
import { aparteGlobalConfig } from '@aparte/core';

aparteGlobalConfig.registerIcons({
  launcherOpen: () => '<svg class="aparte-icon" viewBox="0 0 24 24" fill="currentColor"><path d="M5 3h14a3 3 0 0 1 3 3v9a3 3 0 0 1-3 3h-7l-5 4v-4H5a3 3 0 0 1-3-3V6a3 3 0 0 1 3-3z"/></svg>',
  launcherClose: () => '<svg class="aparte-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2.5" stroke-linecap="round" stroke-linejoin="round"><path d="m6 9 6 6 6-6"/></svg>',
});
```

## Accessibility

- The button's `aria-expanded` follows the state; it is named by its label, or by the locale when
  it shows only the bubble or the ✕.
- The header is a `div`, not a `<header>`: outside a section, a `<header>` is the page's banner
  landmark, and a widget in a corner is not the page's banner. Its buttons are named by the locale,
  and show that name on hover.
- The maximize button's name says what a press will do — "Expand the chat", then "Shrink the chat"
  — the way a window's Maximize turns into Restore, so it carries no `aria-pressed`. A button of
  yours marked `data-aparte-launcher-maximize` keeps its own name, and the launcher keeps its
  `aria-pressed` instead.
- Opening with the button hands the focus to the composer, or to the first control of your card —
  never to the header's ✕; closing gives it back to the button when the focus was inside.
  `show()` and `open` set from a script move no focus, so a page that restores the state on load
  does not steal it. A control of yours that opens the chat with `show()` and wants the composer
  ready focuses it itself, right after.
- Maximizing and bringing back keep the focus on the button that was pressed.
- Escape brings a maximized chat back to its card; otherwise it closes the chat, from anywhere
  inside, unless something there has the key first: a control that
  answered it (a menu closing, the [context gauge](/components/context-gauge/)'s panel), an input
  method that is composing text, or a modal `<dialog>` open in your card, which closes itself on
  it. The next Escape closes the launcher.
- A closed launcher's content is `display: none`, and stays so when your card sets its own
  `display` — inline, or by a rule of any weight: nothing invisible keeps a tab stop.
- While the open chat covers the whole window — the sheet on a phone, or maximized — Tab stays
  inside it; the card, and the panel of `maximizable="panel"`, leave the page reachable.
- The page behind is still in the accessibility tree, since the launcher does not own it. Take
  your page's container out while the chat covers it: `covers`, on the element and in the event,
  says when — the event fires again when the window crosses the breakpoint with the chat open, or
  when it is maximized, so no media query of yours has to match `breakpoint`:

  ```ts
  const launcher = document.querySelector('aparte-launcher');
  const page = document.querySelector('main'); // your page, never an ancestor of the launcher

  launcher?.addEventListener('aparte-launcher-toggle', (event) => {
    if (page) page.inert = event.detail.covers;
  });
  ```
