The words of a reply are a `text` segment, or the message's `content` when it is plain text.
Core has no Markdown dependency: until you install a renderer, it shows the text as it is,
escaped, with its line breaks. Two plugins add the formatting: `@aparte/plugin-marked` renders a
finished reply, `@aparte/plugin-streaming-markdown` renders one while it arrives. Whatever
renders it, the HTML goes through core's sanitizer before it reaches the page.

## Variants

### While it streams

<Variant id="response-streaming" />

With the streaming plugin, each chunk is appended to what is already on screen instead of
re-parsing the whole reply, so a list grows item by item and `**bold` is bold before its closing
marks arrive. When the turn ends, the reply is rendered once more in full.

### With no renderer installed

<Variant id="response-plain" />

The text stays readable and safe; the Markdown marks show as typed.

## Usage

```ts
import { setupMarkedProvider } from '@aparte/plugin-marked';
import { setupStreamingMarkdownProvider } from '@aparte/plugin-streaming-markdown';

setupMarkedProvider(); // a finished reply, in full
setupStreamingMarkdownProvider(); // a reply while it streams
```

`marked` is a peer dependency: install it beside the plugins. The streaming plugin brings its parser with it. The
[Markdown and code](/guides/markdown/) guide covers the options.

## Customize

| Variable | What it sets |
| --- | --- |
| `--aparte-content-font-size` | The size of the reply's text. |
| `--aparte-content-color` | Its colour. Inside a message, `--aparte-message-content-text-user` or `-assistant` takes over when set. |
| `--aparte-content-line-height` | Its line height. |

A table takes the width of its columns, and scrolls sideways when it is wider than the reply.
To have it fill the column instead, at the cost of the scroll:

```css
.aparte-content table { display: table; width: 100%; }
```

Another parser plugs in with `aparteGlobalConfig.setMarkdownProvider(fn)`, a function from
Markdown to HTML. The sanitizer can be replaced with `setHtmlSanitizer()`.

## Accessibility

- Headings, lists, tables and links come out as the HTML elements they are, so a screen reader
  can move through a long reply by heading or by list.
- Tables, quotes and inline code are styled by the same prose sheet as the rest of the reply.
