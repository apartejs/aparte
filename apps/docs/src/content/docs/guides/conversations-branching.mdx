## Turn on retry and edit

```ts
import { aparteGlobalConfig } from '@aparte/core';

aparteGlobalConfig.setBubbleActions({ retry: true, edit: true });
```

Both buttons are off until you turn them on: retry shows on replies, edit on the person's own
messages. With `AparteClient` running — `useAparteClient` in React and Vue,
`createAparteClient` in Svelte and `provideAparte()` in Angular start one — that line is all.
[Buttons](/guides/customization/actions/) lists the others and their order.

## Retry keeps the old answer

A retry asks the model again from the same point and puts the new answer beside the old one, not
over it. As soon as a message has two versions, its footer shows the `‹ 2 / 2 ›` picker, and its
arrows switch the version on screen with nothing for you to wire. `AparteClient` asks again at a
sampling temperature of 0.4, whatever temperature the app set, so the new answer usually differs.
Offered on the person's own messages too —
`setBubbleActions({ user: ['edit', 'retry', 'copy'] })` — a retry answers that message afresh.

## Edit a sent message

The edit button opens the message in an editor: <kbd>Enter</kbd> saves,
<kbd>Shift</kbd>+<kbd>Enter</kbd> starts a new line and <kbd>Escape</kbd> cancels, whatever the
composer's `submit-on-enter`. Saving a changed text sends `aparte-edit` with
`{ messageId, content, targetId }` — an unchanged or empty one just closes the editor — and
`AparteClient` changes the message in place, drops the replies under it and asks again. An edit
does not branch: the old text and its answers are gone. To keep them, handle `aparte-edit` yourself
and keep the old text in your own data; the built-in picker shows only on replies, so a switch
between versions of a question is yours to draw.

## With your own loop

```ts
import type { AparteChatViewport, AparteMessage } from '@aparte/core';

declare const viewport: AparteChatViewport;
declare function streamAnswer(history: AparteMessage[]): AsyncIterable<string>;   // your model

async function answerInto(id: string): Promise<void> {
  // The path on screen, ending in the new empty reply: everything before it is the history.
  const history = viewport.getMessages().slice(0, -1);
  for await (const chunk of streamAnswer(history)) viewport.appendToken(id, chunk);
  viewport.completeMessage(id);
}

document.addEventListener('aparte-retry', (event) => {
  const id = viewport.addSiblingOf(event.detail.messageId, {
    id: crypto.randomUUID(), role: 'assistant', content: '', timestamp: Date.now(),
  });
  if (id) void answerInto(id);
});

document.addEventListener('aparte-edit', (event) => {
  const { messageId, content } = event.detail;
  viewport.updateMessage(messageId, { content });
  viewport.truncateResponsesAfter(messageId);
  const id = viewport.addSiblingOf(messageId, {
    id: crypto.randomUUID(), role: 'assistant', content: '', timestamp: Date.now(),
  });
  if (id) void answerInto(id);
});
```

The buttons only send their event; without a handler, an edit puts the original text back.
`addSiblingOf` reads the role of the message you give it: beside a reply it adds a version of that
reply, under one of the person's messages it adds an answer to it — which is how the edit handler
gets its fresh reply. `truncateResponsesAfter` drops every version of the replies under the edited
message, so the new one starts alone. In React, Vue, Svelte or Angular, the framework package owns
the messages: call `addSiblingOf`, `updateMessage` and `truncateResponsesAfter` on the chat's ref,
and stream with its `injectTokenStream(id, tokens)` in place of `answerInto`.

## While a reply streams

The version arrows, and retry and edit on every message, are disabled until the reply is done;
Stop stays live. `<aparte-chat-viewport>` carries `data-busy` meanwhile, for controls of your own:
`aparte-chat:has(aparte-chat-viewport[data-busy]) .my-button { opacity: 0.5; }`.

## Restyle it or take it back

```ts
import { aparteGlobalConfig } from '@aparte/core';

aparteGlobalConfig.setBubbleActions({ retry: false });     // keep edit, drop retry
aparteGlobalConfig.setBubbleActions({ user: ['copy'] });   // your messages: copy only
```

A `user` or `assistant` list replaces the flags for that role: to drop retry there, leave it out of
the list. The picker needs no switch of its own: it shows only on a message that has versions. Its counter
can be drawn your way, dots for instance, with
[`setSiblingNavRenderer`](/guides/customization/render-hooks/).
