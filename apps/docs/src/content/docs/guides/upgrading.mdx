1.0.0 is the first release under the [stability promise](/reference/stability/): from here on, a
name on the declared surface keeps its name, and what it does, until 2.0. Getting there asks a few
changes of code written against 0.x, and most apps need one or two of them.

## Move every package at once

Every `@aparte/*` package ships at the same version, and each one's peer range on another is now
`>=1.0.0 <2.0.0`. Upgrade them together, every one your `package.json` lists:

```bash
npm install @aparte/core@1 @aparte/react@1 @aparte/plugin-marked@1
```

A 0.x package beside a 1.x one is a peer conflict, and your package manager reports it.

Coming from a release before 0.27? `@aparte/locale-fr` no longer exists, and the same `fr` is in
`@aparte/locales`:

```diff lang="ts"
- import { fr } from '@aparte/locale-fr';
+ import { fr } from '@aparte/locales/fr';
```

The beta also changed a few behaviours along the way, each in the notes of its release; the
[stability page](/reference/stability/#the-beta-017-to-032) lists them with what to change.

## Pictures wait for a click

A picture a model or a tool chose no longer loads by itself. `data:` and `blob:` pictures do; any
other shows as a link that names its host, and loads when the reader clicks it. A card shows one
"Show images" button in place of its pictures, and nothing is fetched while a reply streams.

Allow the places your own pictures come from:

```ts
import { aparteGlobalConfig } from '@aparte/core';

aparteGlobalConfig.setImagePolicy(['self', 'https://cdn.example.com']);
```

`['*']` loads every picture, as 0.x did. [Pictures a reply can load](/guides/markdown/#pictures-a-reply-can-load)
gives the whole rule, and why a picture waits by default.

## What 1.0 removes

Each of these was marked deprecated during the beta. If your code uses none of them, there is
nothing to do here.

**`<aparte-context auto-compact>`.** Remove the attribute: the gauge no longer asks for a
compaction, and `@aparte/plugin-compaction` compacts by itself once it is set up, past 80 % of the
window by default.

```diff lang="html"
- <aparte-context auto-compact></aparte-context>
+ <aparte-context></aparte-context>
```

**The `window` of an `aparte-compact` request.** It is no longer read. Give `setupCompaction` the
window, or let the model declare it:

```ts
import { setupCompaction } from '@aparte/plugin-compaction';

setupCompaction({ contextWindow: 128_000 });
```

**A `CompactionTarget` without `updateMessage`.** The type now requires it, and `clearAll` and
`appendMessage` left it: since 0.26.0 a compaction writes one checkpoint through `updateMessage` and
calls nothing else.

```diff lang="ts"
  const target: CompactionTarget = {
      getMessages: () => store.messages,
-     appendMessage: (message) => store.append(message),
-     clearAll: () => store.clear(),
+     updateMessage: (id, updates) => store.update(id, updates),
  };
```

**The `compactionSummaryTitle` locale key.** Remove it from your locale. Nothing has read it since
0.26.0, and the nine locales of `@aparte/locales` no longer carry it.

**The viewport's `clearMessages()`.** Call `clearAll()`, which also removes the bubbles.
`clearMessages()` on `<aparte-chat>`, on the framework components and on the imperative API is
unchanged.

```diff lang="ts"
- viewport.clearMessages();
+ viewport.clearAll();
```

**`AparteMessageBranch`, and the `branches` and `activeBranchIndex` fields of `AparteMessage`.**
Nothing read them. Branches are the message tree: `addSiblingOf`, `navigateBranch` and the
`aparte-path-changed` event, in [Conversations and branching](/guides/conversations-branching/).

**`AparteCodeSegment.showLineNumbers` and `AparteErrorSegment.stack`.** Nothing read them either;
put a stack in the error's `details`.

## Behaviours that changed

These keep their names; what they do moved. Most apps meet none of them.

- **Suggestion buttons the model writes send their label.** In a `suggestions` block, a
  `{ "label", "prompt" }` reply sends its label and the `prompt` is ignored, because the block is
  model text and the button must send what it shows. Suggestions your app passes are unchanged.
- **A card the model wrote draws only the links among its actions.** A card's `actions` receives
  `{ origin }` as its second argument — `'tool'`, `'segment'` or `'fence'` — and a card the model
  wrote as a code block (`'fence'`) shows its links and drops its other buttons.
- **A reply cannot drive your page's controls.** Markup in a message no longer carries the
  attributes core reads as controls (`data-aparte-dialog-open` and the rest), and `<input>` in a
  reply is limited to a disabled checkbox. Change your code only if a custom segment renderer, a
  tool's `details` string or a custom sanitizer's output relied on them.
- **The server handlers answer 415 to a body that is not declared JSON.** `createAparteAgentHandler`
  and `createAparteChatHandler` refuse a request whose `Content-Type` is not `application/json`.
  `AparteBackendTransport` sends it; a bare `fetch` with a JSON body must set the header.
- **A link with a scheme and no slash is an external link.** `[docs](http:example.com/x)` opens in a
  new tab like any other external link.
- **A Mermaid node picture from a URL is not drawn.** The diagram shows its source instead, since
  drawing it sent a request to that address; an inline `data:image/…` picture still draws.
- **`@aparte/runner-n8n` shows a Chat node's buttons only when their links resume the running
  execution**, and an n8n error frame no longer puts the workflow's own words in front of the
  person.

The [changelog](/changelog/) has each of these in full, with the release it came in.
