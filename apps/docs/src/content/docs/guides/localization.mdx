The chat's own words — the composer's placeholder, the Copy and Retry buttons, "Thinking", the
names a screen reader hears — come from a locale. English is built in, as
`APARTE_DEFAULT_LOCALE`, so a chat with no locale set is in English.

## Switch language

```bash
npm install @aparte/locales
```

```ts
import { aparteGlobalConfig } from '@aparte/core';
import { fr } from '@aparte/locales/fr';

aparteGlobalConfig.setLocale(fr);
```

The switch is live: the chats already on the page relabel at once, so it can happen at any time,
before or after they render. A chat with a [configuration of its own](/guides/customization/#per-chat-configuration)
has its own locale: call `setLocale(fr)` on that configuration too.

`@aparte/locales` carries nine languages, each its own entry, so a page built with a bundler loads
only the one it imports. French used to ship alone as `@aparte/locale-fr`, which 0.27.0 removes:
the same `fr` is now `@aparte/locales/fr`.

| Language | Import | `tag` |
| --- | --- | --- |
| French | `import { fr } from '@aparte/locales/fr'` | `fr-FR` |
| Spanish | `import { es } from '@aparte/locales/es'` | `es` |
| Portuguese (Brazil) | `import { ptBR } from '@aparte/locales/pt-BR'` | `pt-BR` |
| German | `import { de } from '@aparte/locales/de'` | `de` |
| Italian | `import { it } from '@aparte/locales/it'` | `it` |
| Russian | `import { ru } from '@aparte/locales/ru'` | `ru` |
| Japanese | `import { ja } from '@aparte/locales/ja'` | `ja` |
| Korean | `import { ko } from '@aparte/locales/ko'` | `ko` |
| Chinese (Simplified) | `import { zhCN } from '@aparte/locales/zh-CN'` | `zh-CN` |

Each one translates every string core draws, keeps English's placeholders, and is written left to
right; the package's tests check all three for every language. To follow the browser's language,
with English when none matches:

```ts
import { aparteGlobalConfig } from '@aparte/core';
import { de, es, fr } from '@aparte/locales';

const byLanguage = { de, es, fr };
const language = navigator.language.slice(0, 2) as keyof typeof byLanguage;
if (byLanguage[language]) aparteGlobalConfig.setLocale(byLanguage[language]);
```

To download the visitor's language alone, load it when it is needed. Write each import out in
full: a bundler splits an import it can read, and a path built from a variable is not one.

```ts
import { aparteGlobalConfig } from '@aparte/core';
import type { AparteLocale } from '@aparte/core';

const languages: Record<string, () => Promise<AparteLocale>> = {
  fr: () => import('@aparte/locales/fr').then((m) => m.fr),
  de: () => import('@aparte/locales/de').then((m) => m.de),
  'pt-BR': () => import('@aparte/locales/pt-BR').then((m) => m.ptBR),
};

const load = languages[navigator.language] ?? languages[navigator.language.slice(0, 2)];
void load?.().then((locale) => aparteGlobalConfig.setLocale(locale));
```

The chat shows English until the language lands, then switches, as on any change of locale.

## Let the person choose

```ts
import { aparteGlobalConfig } from '@aparte/core';
import { fr } from '@aparte/locales/fr';

function setLanguage(lang: 'fr' | 'en'): void {
  if (lang === 'fr') aparteGlobalConfig.setLocale(fr);
  else aparteGlobalConfig.resetLocale();
}
```

`resetLocale()` puts English back, and `getLocale()` returns the locale in force.

## Write your own locale

```ts
import { aparteGlobalConfig, APARTE_DEFAULT_LOCALE, type AparteLocale } from '@aparte/core';

const es: AparteLocale = {
  ...APARTE_DEFAULT_LOCALE,
  tag: 'es-ES',
  inputPlaceholder: 'Escribe un mensaje…',
  sendButton: 'Enviar',
  copy: 'Copiar',
  approvalAsk: '¿Ejecutar {tool}?',
};

aparteGlobalConfig.setLocale(es);
```

Start from the English default and override the keys you translate: the type lists the chat's
built-in strings, and a key you leave out shows in English. These keys take a placeholder the
chat fills in: `{tool}` in `approvalAsk`, `{name}` in `removeAttachment`, `{title}` in
`deleteConversationConfirm`, `{duration}` in `thoughtFor` (`Thought for {duration}`; the duration
is formatted by `Intl` in the locale's `tag`), `{instruction}` in `toolRejectedSaid` and `{n}` in
`maxTurnsReached` (`Stopped after {n} turns to avoid an endless loop.`; the turn-limit error follows
the locale).

A tool row's notes are keys too: `toolRejectedSaid`, `toolRefusedByPolicy`,
`toolNotRunAfterRefusal`, `toolTimedOut`, `toolUnavailable`, `toolNoApprover` and `toolTurnLimit`.
So are the reasoning block's `thought` ("Thought") and `thoughtFor` (shown with `showDuration`), and two read by plugins:
`questionDeclined` (`@aparte/plugin-ask-user`) and `artifactNotCreated`
(`@aparte/plugin-artifacts`). So are the sentences a failed turn reads as, one per family of error
codes: `errorUnreachable`, `errorTimeout`, `errorRefused`, `errorRateLimited`, `errorTooLong` and
`errorFailed` (see [the error card](/components/error/#what-the-card-says)). Every language of
`@aparte/locales` translates them all.

`tag` and `direction` are not words:

- `tag` is a BCP-47 language tag, such as `'es-ES'`. Message times, the conversation list's dates
  and the context gauge's numbers are formatted for it, so a French locale gets 24-hour times.
  Without it, they follow the browser.
- `direction` is `'ltr'` or `'rtl'`, written as `dir` on the message list and the composer.
  Without it, the chat follows the page: a page that says `<html dir="rtl">` gets a right-to-left
  chat with no locale setting at all.

In a right-to-left chat, what a person or a model wrote keeps its own direction: each message, each
reasoning block and each conversation title reads from its first letter (`dir="auto"`), and the
input follows what is typed on each line, so an English answer in an Arabic page ends with its full
stop on the right. Code, formulas, diagrams and charts always read left to right — and do not
turn an Arabic reply that opens with them; a card follows the message it is in.

## Add strings of your own

```ts
import { aparteGlobalConfig, subscribeConfigChange } from '@aparte/core';
import { fr } from '@aparte/locales/fr';

aparteGlobalConfig.setLocale(fr);
aparteGlobalConfig.extendLocale({ myPluginRetry: 'Réessayer' });

const label = (): string => aparteGlobalConfig.getLocale().myPluginRetry ?? 'Try again';

function mount(el: HTMLElement): () => void {
  const paint = (): void => { el.textContent = label(); };
  paint();
  return subscribeConfigChange(el, paint);
}
```

A locale holds your keys beside the chat's. `extendLocale` merges them into the locale in force;
`setLocale` and `resetLocale` replace the whole object, your keys included, so set the package
first and extend it after, or pass `{ ...fr, myPluginRetry: 'Réessayer' }` in one call — which is
what a language toggle does on every switch. Read your key off `getLocale()` with its English
default at the call site, and repaint on a switch with `subscribeConfigChange`, which returns the
function that stops it. A [segment renderer](/guides/customization/segments/#what-a-renderer-is-called-for)
relabels in its `relabel` callback instead, called on every change.

The status line the framework components show while `isTyping` is set reads their `typingText`
prop, and without one the locale's `typing` key, like `<aparte-chat-status>` itself.

## What stays in English

The words the model reads stay in English whatever the locale, since they are part of the request,
not of the interface: the question tool's description and instructions in
`@aparte/plugin-ask-user` (its `description` and `systemPrompt` options replace them), the
compaction plugin's summary prompt (`prompt`), and the artifacts tool's instructions
(`systemPrompt` on `createArtifactTool`).
