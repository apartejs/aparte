## Pass the run's fields in your route

{/* doc-check: skip excerpt — TanStack AI and its adapter are your packages */}
```ts
// app/api/chat/route.ts
import { chat, chatParamsFromRequest, mergeAgentTools, toServerSentEventsResponse } from '@tanstack/ai';
import { openaiText } from '@tanstack/ai-openai';
import { serverTools } from './tools';

export async function POST(request: Request) {
  let params;
  try { params = await chatParamsFromRequest(request); }
  catch (error) { if (error instanceof Response) return error; throw error; }   // a malformed body
  return toServerSentEventsResponse(chat({
    adapter: openaiText('gpt-5.5'),   // your adapter: any TanStack AI text adapter
    messages: params.messages,
    threadId: params.threadId,
    runId: params.runId,
    parentRunId: params.parentRunId,
    resume: params.resume,
    tools: mergeAgentTools(serverTools, params.tools),
  }));
}
```

[TanStack AI](https://tanstack.com/ai) runs the model, the tools and the approvals, and leaves
the interface to you. Read the request with `chatParamsFromRequest` and hand `chat()` the run's
fields with the messages: `resume`, `threadId`, `runId` and `parentRunId` are what let a paused
run continue. A route that passes only `messages` streams, but an approval or a tool the page ran
never reaches the run. `mergeAgentTools` adds the tools the page declares to yours; a page tool
must not share a name with a server tool, since the server's wins.

## Connect the page

```bash
npm install @aparte/runner-ag-ui @aparte/core
```

```ts
import { AparteClient } from '@aparte/core';
import { createAgUiRunner } from '@aparte/runner-ag-ui';

new AparteClient({
  streamRunner: createAgUiRunner({ endpoint: '/api/chat', relaxedRunFraming: true }),
}).start();
```

The route streams AG-UI, so [`@aparte/runner-ag-ui`](/providers/agent/ag-ui/) draws it as it is:
text, reasoning, tool rows, the approval panel. Your route stays a TanStack AI route.
`relaxedRunFraming` is what lets the runner read it: TanStack AI, 1.0 included, closes each model
step with a `RUN_FINISHED` and answers a resume before its `RUN_STARTED`, a framing AG-UI 1.0 asks a
client to reject. Every other rule of the protocol still holds. Under a
framework, hand the same runner to the wrapper's client: `useAparteClient({ streamRunner })` in
React and Vue, `createAparteClient({ streamRunner })` in Svelte,
`provideAparte({ clientOptions: { streamRunner } })` in Angular.

## Approvals and tools in the page

- **`needsApproval: true`** on a server tool pauses the run. The page asks with its
  [approval panel](/guides/tools/#require-approval-human-in-the-loop), and its
  [approval policy](/components/approval-mode/) can answer first. Approve runs the tool on your
  server; Reject sends `{ approved: false }`, without the words the person wrote, and the row stays
  refused.
- **A tool that needs the page** — `ask_user` through `setupAskUser()`, your own through
  `registerTool` — reaches your route as a declared tool, which `mergeAgentTools` adds. TanStack
  AI pauses on it, the page runs it, and its result resumes the run: TanStack's `.client()`
  implementation is not needed, the page's handler is the implementation. As with any
  [AG-UI agent](/providers/agent/ag-ui/#tools-the-page-runs), the page asks nobody before running
  it.

It works with `@tanstack/ai` <code>{TANSTACK_RANGE}</code>. TanStack AI is on 0.x, where a minor
can change its wire: check that range when you upgrade it.
