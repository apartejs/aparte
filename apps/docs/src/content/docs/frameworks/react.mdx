## Install

```bash
npm install @aparte/react @aparte/core
npm install @aparte/provider-scenario   # a scripted model, to stream with no key
```

`@aparte/core`, `react` and `react-dom` are peer dependencies: React <code>{WRAPPER_PEERS.react}</code>.

## Render the chat

```tsx
import { aparteGlobalConfig } from '@aparte/core';
import { createScenarioProvider } from '@aparte/provider-scenario';
import { showcase } from '@aparte/provider-scenario/showcase';
import { AparteChat, useAparteClient } from '@aparte/react';
import '@aparte/core/styles.css';

aparteGlobalConfig.registerAIProvider(createScenarioProvider({ scenarios: showcase }));

export function Chat() {
  useAparteClient();
  return <AparteChat centerWhenEmpty emptyState={<p>Ask me anything…</p>} />;
}
```

That is a whole chat: `<AparteChat>` keeps its own thread, and the client `useAparteClient` starts
streams each reply into it from the scripted model — no state of yours, no key. In the Next App
Router, put `'use client'` at the top of this file: hooks run in a client component — a server
component can render `<AparteChat>` itself, the package is a client boundary. Next renders it to
HTML on the server, and the browser hydrates it with no mismatch: the elements wait until React has
the page ([Hydration](/frameworks/elements/#hydration)). This is tested in CI: a Next {T.next} App
Router page built for production, served, and checked in a browser.

## Hold the messages yourself

```tsx
import { AparteChat, useAparteChat, useAparteClient } from '@aparte/react';

export function Chat() {
  const chat = useAparteChat();
  useAparteClient();
  return <AparteChat ref={chat.ref} messages={chat.messages} onMessagesChange={chat.setMessages} />;
}
```

When the messages are yours to read or store, `useAparteChat` holds them and the component's ref:
hand both to `<AparteChat>`. The person's message is added when they send, so do not add it
yourself; `onMessageSent` fires after, for a side effect.

## Stream a model

`useAparteClient` starts a client when the component mounts, stops it when it unmounts, and returns
`{ client, abort }`. It takes the `AparteClientOptions` and builds the client once, on the first
render. Its function options — `keyResolver`, `approvalResolver`, `requestInterceptor`,
`history`, `targetResolver` and `fileInjectFilter` — are called from the latest render, so one
that reads state sees the state of now. `streamRunner` is read once and handed to the client as it
is (the client recognises the engine's own loop by identity), so a runner that reads state reads
it through a ref; the other options are read once too, so remount the component with a new `key`
to change them. For a real model, register its
provider, name the model and give the key — `aparteGlobalConfig.setModelConfig({ defaultProvider:
'openrouter', defaultModel: 'openai/gpt-4o-mini' })` and `useAparteClient({ keyResolver })`
([Connect a model](/providers/)). A `config` prop gives one `<AparteChat>` providers and a
transport of its own; give its client the same one, `useAparteClient({ config })`. With the client
running, turn on retry and edit with `aparteGlobalConfig.setBubbleActions({ retry: true, edit: true })`
([Buttons](/guides/customization/actions/)).

## Put your own UI in it

```tsx
<AparteChat
  ref={chat.ref}
  messages={chat.messages}
  onMessagesChange={chat.setMessages}
  emptyState={<p>Ask me anything…</p>}
  toolbar={<span className="hint">Shift + Enter for a new line</span>}
/>
```

| Prop | What it fills |
| --- | --- |
| `emptyState` | the chat before the first message |
| `aboveComposer` | the space above the composer |
| `toolbar` | the composer's bottom row, not drawn when you pass `composer` ([The composer toolbar](/guides/customization/composer-toolbar/)) |
| `composer` | the composer, replaced by yours |
| `renderBubble(message)` | each message, drawn by you ([Bubble](/guides/customization/bubble/#your-own-element-in-a-framework)) |

The component takes these and no children.

## Your components in tool calls

```tsx
import { AparteToolUI } from '@aparte/react';

export function WeatherCards() {
  return (
    <AparteToolUI<{ city: string }> name="get_weather">
      {(tool) => <p>{tool.input.city}: {tool.status === 'resolved' ? tool.result : 'looking it up…'}</p>}
    </AparteToolUI>
  );
}
```

Mounted anywhere under your providers, `<AparteToolUI>` draws every call to that tool with your
component, through a portal — so the card reads your contexts — mounted once per call and updated in
place, until it unmounts and the calls go back to core's row. `<AparteSegmentUI type="…">` does the
same for a segment type ([Your components in tool calls](/guides/tool-ui/)).

## Props and callbacks

```tsx
<AparteChat id="support" className="flex-1 min-h-0" loading={isFetchingHistory} attachments />
```

The ones you reach for: `placeholder`, `disabled` and `submitOnEnter`; `typeToFocus`
([where a typed key goes](/components/composer/#customize)); `stopKey`, a key that stops the
reply (`"Escape"`); `centerWhenEmpty`;
`loading`, for a wait of your own; `isTyping` and `typingText`, a waiting line you drive yourself;
`overlayComposer`; `attachments`, off by default ([Attachments](/guides/attachments/));
`elicitation={false}` when you draw the questions yourself; `conversationId`, `config` and
`layoutTransitionMs`, how long the list holds its layout after a conversation swap. The root takes
`className` and `style`. `id` is the chat's id, which every event carries: for two chats on one page,
each answered by its own client, give each an `id` and its client `scopeToTargetId` with it. The
callbacks — `onMessageSent`, `onAction`, `onMessagesChange`, `onMessageAppended`, `onTypingChange`
and `onConversationCreated` — are beside the other frameworks' in
[Wrapper surface](/reference/wrappers/#callbacks).

## Control it from code

`chat.ref`, and the helpers `useAparteChat` returns beside it, are the chat's imperative API:
`appendMessage`, `addSegment`, `injectTokenStream`, `scrollToBottom`, `focusInput` and the rest, to
drive the chat from a loop of yours ([Your own loop](/guides/bring-your-own-loop/)).
`useConversationManager()` lists, creates, archives and pins saved conversations once you call
`init(adapter)` with your storage adapter — and the chat's `config` as second argument, if it has
one — and the chat switches between them through `conversationId`
([Save conversations](/guides/conversation-persistence/)).

For an event the chat has no prop for — a plugin's, such as `aparte-subagent-open`, or your own —
`chat.getElement()` is the chat's root element (every event of the chat reaches it) and
`chat.getComposer()` its `<aparte-composer>`. `useAparteEvent` listens on it, typed by
`HTMLElementEventMap`, which each plugin augments, and always calls your latest handler:

```tsx
import { useState } from 'react';
import { AparteChat, useAparteChat, useAparteEvent } from '@aparte/react';
import '@aparte/plugin-subagents';   // its events join HTMLElementEventMap

function Chat() {
  const chat = useAparteChat();
  const [, setOpenAgent] = useState<string | null>(null);
  // A sub-agent's line asks to be opened beside the chat (`setupSubagents({ open: 'event' })`).
  useAparteEvent(chat.ref, 'aparte-subagent-open', (event) => setOpenAgent(event.detail.agentId));
  return <AparteChat ref={chat.ref} messages={chat.messages} onMessagesChange={chat.setMessages} />;
}
```

## Any element, typed

Every element of core is a component: `<AparteConversationList>`, `<AparteSelect>`, `<AparteSplit>`,
`<AparteLauncher>`… The tag's attributes are its props, by the names the tag has; a property such as
the list's `conversations` is a prop too; and each event is an `onXxx` callback, called with the
event's detail and then the event itself. The ref is the element.

```tsx
import { useState } from 'react';
import { AparteOption, AparteSelect } from '@aparte/react';

export function ModelPicker() {
  const [model, setModel] = useState('gpt-4o-mini');
  return (
    <AparteSelect value={model} searchable placeholder="Pick a model" onSelectChange={(detail) => setModel(detail.value)}>
      <AparteOption value="gpt-4o-mini">GPT-4o mini</AparteOption>
      <AparteOption value="gpt-4o">GPT-4o</AparteOption>
    </AparteSelect>
  );
}
```

A presence attribute (`searchable`) is `true` or `''` to set it and `false`, `null` or `undefined` to
remove it; every other attribute takes `null` too, so `active-id={history.activeId}` is a
`string | null` as it stands. `className`, `style`, `children`, `id`, `aria-*` and `data-*` go on the
element as React writes them. `event.preventDefault()` cancels an event that can be cancelled — the
conversation list's rename, pin and delete, say ([the list, bound to `useConversationManager()`](/components/conversation-list/#in-react)).
Every component, with its props type and callbacks, is in the
[reference](/reference/wrappers/#a-react-component-for-every-element); `<AparteChat>` is the chat's.

They are components, not the raw tag, because React 18 and 19 disagree about a custom element's
props. React 18 writes a property as the text `[object Object]` and listens to no event; React 19
assigns a prop as a property when the element has one of that name and as an attribute when it does
not, so the same prop takes a different path in each. A component writes its props itself, after the
render and the same way under both: attributes through core's `applyElementProps`, properties by
assignment, events with `addEventListener`. It writes a prop when its value changed, a callback that
changes takes no new listener, and on a server render the element carries `defer-hydration` until
React has hydrated it, as `<AparteChat>`'s root does.

The raw tag is typed too — importing from `@aparte/react` types every element of core as JSX — for
what you already have: `<aparte-select searchable="" placeholder="Pick a model">`, with `''` to be on
and `null` or `undefined` to be off, and an event read by ref
([Elements, typed](/frameworks/elements/)). A plugin's element is typed by the plugin, and one of
yours by you ([your own element](/frameworks/elements/#your-own-element-or-a-plugins)). `<AparteUi>`
mounts any tag by its name and sets its props; it forwards core's events, so name your element's own
in `events`. A ref to it gives `getElement()` and `callMethod(name, ...args)`:

{/* doc-check: skip excerpt — a JSX line inside your component */}
```tsx
<AparteUi name="my-token-counter" props={{ 'data-budget': '8000' }} events={['token-count']} onElementEvent={(e) => setCount(e.detail)} />
```
