Tested in CI with Svelte {T.svelte[0]} and {T.svelte[1]}: in the two examples a browser drives, and in a SvelteKit {T.sveltekit} page rendered on the server and hydrated.

## Install

```bash
npm install @aparte/svelte @aparte/core
npm install @aparte/provider-scenario   # a scripted model, to stream with no key
```

`@aparte/core` and `svelte` are peer dependencies: Svelte <code>{WRAPPER_PEERS.svelte}</code>. The
package ships its `.svelte` sources, which your build compiles. On Svelte 5, import from
`@aparte/svelte/runes` — props, snippets, `bind:messages` and callback props, written in runes
(Svelte <code>{WRAPPER_PEERS.svelteRunes}</code>). The package root keeps the component written in Svelte 4's syntax, which
runs on both majors ([Svelte 4](#svelte-4)).

## Render the chat

```svelte
<script lang="ts" module>
  import { aparteGlobalConfig } from '@aparte/core';
  import { createScenarioProvider } from '@aparte/provider-scenario';
  import { showcase } from '@aparte/provider-scenario/showcase';

  aparteGlobalConfig.registerAIProvider(createScenarioProvider({ scenarios: showcase }));
</script>

<script lang="ts">
  import { AparteChat, createAparteClient } from '@aparte/svelte/runes';
  import '@aparte/core/styles.css';

  createAparteClient();
</script>

<AparteChat centerWhenEmpty>
  {#snippet emptyState()}<p>Ask me anything…</p>{/snippet}
</AparteChat>
```

That is a whole chat: `<AparteChat>` keeps its own thread, and the client `createAparteClient` starts
streams each reply into it from the scripted model — no state of yours, no key. The module script
runs once, however many times the component mounts.

## Hold the messages yourself

```svelte
<script lang="ts">
  import { AparteChat, createAparteClient, type AparteMessage } from '@aparte/svelte/runes';

  let messages = $state<AparteMessage[]>([]);
  createAparteClient();
</script>

<AparteChat bind:messages />
```

When the messages are yours to read or store, `bind:messages` keeps your state in step with what
the chat does, and a write of yours — a new array, or a `push` — reaches the transcript. The person's message is added when they
send, so do not add it yourself; `onmessageSent` fires after, for a side effect.

## Stream a model

`createAparteClient` starts a client when the component mounts, stops it when it is destroyed, and
returns `{ client, abort }`; it takes the `AparteClientOptions`. For a real model, register its
provider, name the model and give the key — `aparteGlobalConfig.setModelConfig({ defaultProvider:
'openrouter', defaultModel: 'openai/gpt-4o-mini' })` and `createAparteClient({ keyResolver })`
([Connect a model](/providers/)). A `config` prop gives one `<AparteChat>` providers and a
transport of its own; give its client the same one, `createAparteClient({ config })`. With the
client running, turn on retry and edit with
`aparteGlobalConfig.setBubbleActions({ retry: true, edit: true })` ([Buttons](/guides/customization/actions/)).

## Callbacks

Each callback — `onmessageSent`, `onaction`, `onmessagesChange`, `onmessageAppended`,
`ontypingChange`, `onconversationCreated` — is a prop that gets the payload itself:
`onconversationCreated={(id) => goto('/chat/' + id)}`. The names are the ones Svelte's own migration
gives a `dispatch('messageSent')`: `on`, then the event.

## Put your own UI in it

```svelte
<AparteChat bind:messages>
  {#snippet emptyState()}<p>Ask me anything…</p>{/snippet}
  {#snippet toolbar()}<span class="hint">Shift + Enter for a new line</span>{/snippet}
  {#snippet bubble(message)}<MyBubble {message} />{/snippet}
</AparteChat>
```

| Snippet | What it fills |
| --- | --- |
| `emptyState` | the chat before the first message |
| `aboveComposer` | the space above the composer |
| `toolbar` | the composer's bottom row, not drawn when you fill `composer` ([The composer toolbar](/guides/customization/composer-toolbar/)) |
| `composer` | the composer, replaced by yours |
| `bubble(message)` | each message, drawn by you ([Bubble](/guides/customization/bubble/#your-own-element-in-a-framework)) |

## Your components in tool calls

```svelte
<script lang="ts">
  import { AparteToolUI } from '@aparte/svelte/runes';
  import WeatherCard from './WeatherCard.svelte';
</script>

<AparteToolUI name="get_weather">
  {#snippet children(tool)}<WeatherCard {tool} />{/snippet}
</AparteToolUI>
```

Mounted anywhere in your app, `<AparteToolUI>` draws every call to that tool with your snippet,
mounted with the contexts of where you declare it — so `getContext` finds what your app set there —
once per call and updated in place, until it unmounts and the calls go back to core's row.
`<AparteSegmentUI type="…">` does the same for a segment type
([Your components in tool calls](/guides/tool-ui/)).

## Props

```svelte
<AparteChat id="support" class="flex-1 min-h-0" loading={isFetchingHistory} attachments />
```

The ones you reach for: `placeholder`, `disabled` and `submitOnEnter`; `centerWhenEmpty`;
`loading`, for a wait of your own; `isTyping` and `typingText`, a waiting line you drive yourself;
`overlayComposer`; `attachments`, off by default ([Attachments](/guides/attachments/));
`elicitation={false}` when you draw the questions yourself; `conversationId`, `config` and
`layoutTransitionMs`, how long the list holds its layout after a conversation swap. The root takes
`class` and a `style` string. `id` is the chat's id, which every event carries: for two chats on one
page, each answered by its own client, give each an `id` and its client `scopeToTargetId` with it
([Wrapper surface](/reference/wrappers/)).

## Control it from code

```svelte
<script lang="ts">
  import { AparteChat, type AparteChatImperativeApi } from '@aparte/svelte/runes';

  let chat = $state<AparteChatImperativeApi>();
</script>

<AparteChat bind:this={chat} />
<button onclick={() => chat?.focusInput()}>Ask</button>
```

Bound, the component is the chat's imperative API — `appendMessage`, `addSegment`,
`injectTokenStream`, `scrollToBottom`, `focusInput`, `setConversationId` and the rest — to drive the
chat from a loop of yours ([Your own loop](/guides/bring-your-own-loop/)). `createConversations()`
lists, creates, archives and pins saved conversations as reactive state once you call
`init(adapter)` with your storage adapter, and the chat switches between them through
`conversationId` ([Save conversations](/guides/conversation-persistence/)).

## Any element, typed

```svelte
<aparte-select searchable="" placeholder="Pick a model" onaparte-select-change={(e) => (model = e.detail.value)}>
  <aparte-option value="gpt-4o-mini">GPT-4o mini</aparte-option>
</aparte-select>
```

Importing from `@aparte/svelte` declares every element of core in `SvelteHTMLElements`, so
`svelte-check` covers its attributes and its event attributes: a presence attribute takes `''` to be
on and `null` to be off ([Elements, typed](/frameworks/elements/)). A plugin's element is typed by
the plugin, and one of yours by you
([your own element](/frameworks/elements/#your-own-element-or-a-plugins)). `<AparteUi>` mounts any
tag and sets its props; it forwards core's events, so name your element's own in `events`:

```svelte
<AparteUi bind:this={ui} name="my-token-counter" props={{ 'data-budget': '8000' }} events={['token-count']} onelementEvent={(e) => (count = e.detail)} />
```

`onelementEvent` gets the element's own event. Bound, it gives `ui.getElement()` and
`ui.callMethod(name, ...args)`.

## SvelteKit and tests

Under SvelteKit, render the chat with server rendering on: the server sends its HTML, and the
browser hydrates it with no mismatch — the elements wait until Svelte has the page
([Hydration](/frameworks/elements/#hydration)). Register your provider in the page's
`<script module>`, and call `createAparteClient()` in the component: the client starts in the
browser only. This is tested in CI: a SvelteKit {T.sveltekit} page with `@sveltejs/adapter-node`,
built for production, served, and checked in a browser. `@aparte/core` imports on a server through
its entry without elements ([On the server](/frameworks/elements/#on-the-server)). Vitest runs on
Node, so alias
`@aparte/core` to `@aparte/core/browser` for the elements to upgrade
([Testing your components](/frameworks/elements/#testing-your-components)).

A whole chat site in Svelte — the conversation sidebar, the header, settings, tools and the
scripted model — is [the Svelte 5 example](https://github.com/apartejs/aparte/tree/main/apps/examples/svelte5),
and [the Svelte 4 one](https://github.com/apartejs/aparte/tree/main/apps/examples/svelte4).

## Svelte 4

The package root, `@aparte/svelte`, keeps the component written in Svelte 4's syntax: slots
(`<p slot="empty-state">`, `<svelte:fragment slot="bubble" let:message>`), each callback as a prop
and as a component event (`on:messagesChange`, the payload under `event.detail`), and store helpers
— `createAparteChat()` for the messages, `createConversationManager()` for saved conversations. It
runs on Svelte 4 and on Svelte 5, and its surface is the same as the runes component's, checked on
every build.

```svelte
<script lang="ts">
  import { AparteChat, createAparteClient } from '@aparte/svelte';

  createAparteClient();
</script>

<AparteChat centerWhenEmpty>
  <p slot="empty-state">Ask me anything…</p>
</AparteChat>
```

0.26.0 makes the runes components the package root and moves this one to
`@aparte/svelte/legacy`; on Svelte 5, start from `@aparte/svelte/runes`.
