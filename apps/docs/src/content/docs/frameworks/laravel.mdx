[`apartejs/laravel`](https://github.com/apartejs/laravel) is a Composer package that ships the chat
already built and connects it to the [Laravel AI SDK](https://laravel.com/docs/ai-sdk). Your app needs
no React and no front-end build, and the model runs on your server, so API keys stay in `.env`. Replies
stream with Markdown, tool calls show as they run, and a person can approve or refuse them. Each
person's conversations can be kept in your database and listed in the chat. To add aparté's plugins,
you build the chat with your own Vite: see [Add plugins](#add-plugins).

It needs PHP 8.3+, Laravel 12 or 13 and `laravel/ai` 1.3+.

## Install

```bash
composer require apartejs/laravel
php artisan vendor:publish --provider="Laravel\Ai\AiServiceProvider"
php artisan migrate
```

The last two are the SDK's own setup: its configuration and the tables that keep conversations.

## Render the chat

An agent that keeps its conversations:

```php
namespace App\Ai\Agents;

use Laravel\Ai\Concerns\RemembersConversations;
use Laravel\Ai\Contracts\Agent;
use Laravel\Ai\Contracts\Conversational;
use Laravel\Ai\Promptable;

class Assistant implements Agent, Conversational
{
    use Promptable, RemembersConversations;

    public function instructions(): string
    {
        return 'You are a helpful assistant.';
    }
}
```

A route, and the chat in a view. Give it a height:

```php
// routes/web.php
Route::aparte('/chat', App\Ai\Agents\Assistant::class);
```

```blade
<x-aparte::chat endpoint="/chat" style="height: 32rem" />
```

Inside a Livewire component it works as is: it is excluded from Livewire's re-renders, and a
conversation survives `wire:navigate`.

The route spends your model budget and runs your tools, so give it the middleware your app needs:

```php
Route::aparte('/chat', App\Ai\Agents\Assistant::class)->middleware(['auth', 'throttle:20,1']);
```

## A button in the corner of the page

```blade
<x-aparte::launcher endpoint="/chat" label="Help" />
```

The chat opens above the button under a [header](/components/launcher/#the-header): a title (the
button's `label` unless you set `heading`), a line under it, and a ✕. Add `maximizable` for a button in
the header that [maximizes](/components/launcher/#maximize) the chat to the whole window, or
`maximizable="panel"` for a full-height panel along the edge that keeps the page in view:

```blade
<x-aparte::launcher
    endpoint="/chat"
    label="Help"
    heading="Support"
    subheading="Usually answers in a minute"
    maximizable
/>
```

Escape brings a maximized chat back to its card, `header="false"` leaves the header out, and its
colours are yours to set in CSS. This needs `apartejs/laravel` 0.3 or later.

## Filament

The plugin works with Filament 4 and 5:

```php
use Aparte\Laravel\Filament\ApartePlugin;

$panel->plugin(ApartePlugin::make()->agent(App\Ai\Agents\Assistant::class)->label('Assistant'));
```

Every page of the panel gets the button, for whoever is signed in to it. The route is added for you,
behind the panel's authentication, and the chat follows the panel's light or dark mode.

The chat opens under a header titled with the `label`. A different title, a line under it and a
maximize button are options of the plugin; there is no maximize button unless you call
`maximizable()`:

```php
$panel->plugin(
    ApartePlugin::make()
        ->agent(App\Ai\Agents\Assistant::class)
        ->label('Assistant')
        ->heading('Shop assistant')
        ->subheading('Answers about your orders')
        ->maximizable(), // or ->maximizable('panel') to keep the page in view
);
```

These options need `apartejs/laravel` 0.3 or later.

To keep each person's conversations and list them in the chat, publish the table once (see
[Keep conversations](#keep-conversations)) and call `conversations()`:

```php
$panel->plugin(
    ApartePlugin::make()
        ->agent(App\Ai\Agents\Assistant::class)
        ->maximizable()
        ->conversations(),
);
```

A menu button in the chat's header opens the list, a drawer in the chat's card and a column beside
the chat once it is maximized. The routes are added behind the panel's authentication, and each
panel keeps a list of its own.

## Keep conversations

The chat keeps what is on screen for the tab. To keep it for the person signed in, on every device,
publish the package's table:

```bash
php artisan vendor:publish --tag=aparte-migrations
php artisan migrate
```

Add the routes beside the chat's, behind the middleware that signs people in, and name them on the
component:

```php
// routes/web.php
Route::middleware(['auth'])->group(function () {
    Route::aparte('/chat', App\Ai\Agents\Assistant::class);
    Route::aparteConversations('/chat/conversations');
});
```

```blade
<x-aparte::chat endpoint="/chat" conversations="/chat/conversations" style="height: 32rem" />
<x-aparte::launcher endpoint="/chat" conversations="/chat/conversations" label="Help" maximizable />
```

The floating chat then draws its list itself, in its card. A conversation opens as it was left, tool
calls included, and deleting it from the list also deletes the model's memory of it in the SDK.

- **Each list has a scope.** Two chats that answer with two agents keep two lists: the routes of the
  second one name their own, `Route::aparteConversations('/help/conversations', 'help')`.
- **If the server does not answer,** the chat goes on, and what is said is sent once it answers
  again. A conversation the server refuses (heavier than `conversations.max_bytes`, 2 MB, or sent
  once nobody is signed in) is not kept, and the page is told with an `aparte-conversations-problem`
  event.
- **Limits** are in `config/aparte.php`, and the routes take your own middleware:
  `Route::aparteConversations('/chat/conversations')->middleware('throttle:120,1')`.
- **Elsewhere than that table:** bind your own `Aparte\Laravel\Conversations\ConversationRepository`.

This needs `apartejs/laravel` 0.4 or later.

## A list in your own layout

The list, a new-chat button and the conversation's title can sit anywhere in a view, around the
chat, with no script: aparté's own [sidebar](/components/sidebar/) and
[conversation list](/components/conversation-list/), and two attributes of the package.

```blade
<div class="aparte-app-shell" style="height: 40rem" wire:ignore>
    <aparte-sidebar>
        <div class="aparte-sidebar__header">
            <button type="button" class="aparte-btn aparte-btn--surface" data-aparte-new-chat>New chat</button>
        </div>
        <div class="aparte-sidebar__body">
            <aparte-conversation-list manage></aparte-conversation-list>
        </div>
    </aparte-sidebar>
    <header class="aparte-app-header">
        <button type="button" class="aparte-btn aparte-app-header__toggle" data-aparte-sidebar-toggle>Chats</button>
        <span class="aparte-app-header__title" data-aparte-title>New chat</span>
    </header>
    <div class="aparte-app-shell__main">
        <x-aparte::chat endpoint="/chat" conversations="/chat/conversations" style="height: 100%" />
    </div>
</div>
```

An element belongs to the chat in the same block as it. With several chats on a page, give a chat an
id (`<x-aparte::chat id="support" ...>`) and name it on the element: `for="support"`. Without
`conversations`, the list shows the tab's conversations.

## Approve tool calls

A tool that needs a person uses the SDK's approvals:

```php
public function tools(): iterable
{
    return [(new SendInvoice)->requireApproval('Sending an invoice.')];
}
```

The chat asks before the tool runs. The model answers a refusal, and reads what the person typed in
its place. A pending question comes back after a reload.

## Add plugins

The built chat draws Markdown, tool calls and approvals. To add aparté's plugins, such as
[cards](/guides/cards/), [maths](/guides/math/), [diagrams](/guides/diagrams/), [charts](/guides/charts/)
or code highlighting, or cards of your own, build the chat with your app's Vite instead. The plugins and the chat then share one copy of aparté, which a plugin
installed beside the built chat would not.

Tell the package to stop serving its own copy, in `.env`:

```bash
APARTE_ASSETS=vite
```

Install the chat and the plugins you want:

```bash
npm install @aparte/core@^1 @aparte/runner-ag-ui@^1 @aparte/plugin-marked@^1 marked
npm install @aparte/plugin-katex@^1 katex
```

Give the chat an entry of its own, which imports the package's script and adds each plugin to every
chat with `onAparteSetup`:

```js
// resources/js/chat.js
import { onAparteSetup } from '../../vendor/apartejs/laravel/resources/js/aparte.js';
import 'katex/dist/katex.min.css';
import { setupKatex } from '@aparte/plugin-katex';

onAparteSetup((config) => setupKatex({}, config));
```

Add it to the inputs in `vite.config.js`, so that the production build has it:

```js
laravel({ input: ['resources/css/app.css', 'resources/js/app.js', 'resources/js/chat.js'] }),
```

Load it on the pages that show a chat, with `@vite('resources/js/chat.js')`. In a Filament panel:

```php
use Filament\View\PanelsRenderHook;
use Illuminate\Support\Facades\Blade;

$panel->renderHook(PanelsRenderHook::HEAD_END, fn (): string => Blade::render("@vite('resources/js/chat.js')"));
```

A separate entry keeps your `app.js` out of the panel: a second Alpine, or your app's styles, would
break Filament's.

- `onAparteSetup` receives each chat's config, the chat element, and its options: `options.storage`
  (where its conversations are kept) and `options.client.streamRunner` (what answers it) are yours to
  replace before the chat starts, with any aparté [storage adapter](/guides/conversation-persistence/)
  or [runner](/providers/). What it returns, if a function, runs when the chat stops. Call it at the
  top level of that entry and keep it synchronous: a chat starts once the entry has run.
- The import reads from `vendor/`, so run `composer install` before `npm run build`, in CI and Docker
  builds too.
- If you install the package from a local path (a Composer path repository), Vite follows the link to
  the package's own folder: add `resolve: { dedupe: ['@aparte/core', '@aparte/runner-ag-ui',
  '@aparte/plugin-marked', 'marked'] }` to `vite.config.js` so that every import resolves from your app.
- After changing `APARTE_ASSETS` in production, run `php artisan config:cache` again.

This needs `apartejs/laravel` 0.2 or later.

## Good to know

- **The look** is set with aparté's [CSS variables](/guides/theming/). It follows the system's light or
  dark mode; `follow-dark-class` makes it follow Tailwind's `dark` class instead.
- **What is kept:** the SDK keeps the conversation in your database, tied to the signed-in user, and the
  model's memory comes from there. What is on screen is kept for the tab, unless you
  [keep conversations](#keep-conversations).
- **A conversation** is identified by an id the browser creates, or by `thread="..."` on a chat that
  has one conversation and no list.
- **Guests** can chat if your route allows them. Their conversations belong to nobody, so the id is all
  that protects one.
- **In production,** replies stream through nginx and PHP-FPM with no configuration: the SDK tells nginx
  not to buffer them. Each reply in progress holds a PHP worker until it ends, so count them in
  `pm.max_children`.
- **The SDK's AG-UI stream,** which this package reads, is not in its documentation yet, so a new
  `laravel/ai` version could change it.
