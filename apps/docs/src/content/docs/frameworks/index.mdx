`@aparte/core` is web components, so it works in any framework as it is; a wrapper adds the
framework's idiom — refs, events and lifecycle wired for you. Each one gives you:

- **a chat component**, the whole chat with its slots and callbacks;
- **typed tags for every element of core**, real attributes and real events checked by your
  compiler, to place a select, a conversation list or a composer of your own
  ([Elements, typed](/frameworks/elements/)); a plugin's element, like the model selector, is
  typed by the plugin;
- **`AparteToolUI`** — `<ng-template aparteToolUI>` in Angular — which draws a tool call with a
  component of your framework, rendered from where you declare it, with your app's context
  ([Your components in tool calls](/guides/tool-ui/));
- **`AparteUi`** — `AparteUiComponent` in Angular — which mounts any custom element as a
  component, for an element of yours or a third party's.

A wrapper depends on `@aparte/core` alone, never on a provider: register the one you want
([Connect a model](/providers/)).

## The same in all four

The same slots — `empty-state`, `composer`, `above-composer`, `toolbar` and a bubble of your own
— and the same callbacks — `messageSent`, `action`, `messagesChange`, `messageAppended`,
`typingChange` and `conversationCreated` — each in its framework's idiom.
[Wrapper surface](/reference/wrappers/) has the four syntaxes side by side, generated from the
wrappers' source. Without a framework, the elements are the API:
[Installation and first chat](/guides/getting-started/).
