## The promise

From **1.0.0**, aparté follows semantic versioning on the surface below: a frozen name keeps its name,
and what its documentation says it does, until the next major version.

| Frozen | Not frozen |
| --- | --- |
| element tags and the attributes they document | the methods of an element or of an exported class |
| event names | the fields of an interface, an event's `detail` included |
| the functions, classes and constants a package's main entry exports, and each card's entry of `@aparte/plugin-cards` (`/weather`, `/stock`…), which is that package's API | type names, and what any other subpath entry exports (`/icons`, `/core`, `/react`…) |
| the keys of `AparteLocale` | the keys a plugin adds to the locale |
| `--aparte-*` token names | a token's default value; class names, the kit's included; default colours, spacing and English labels; the docs, the example apps, `@aparte/docs-mcp` |

A name added in a 1.x release is frozen from that release. A frozen name leaves in two steps:

1. **A notice, in a minor**: the old name still works, and the [changelog](/changelog/) and its
   JSDoc mark it deprecated — your editor strikes it through — with its replacement.
2. **The removal, in the next major.**

Adding is always allowed: a new optional attribute, a new optional field on an event's `detail`, a
new export. What is not frozen can change in a minor, never in a patch, and the changelog says
what to change: read it before you implement an exported type yourself, or build on a class name.

One exception, for security. A fix that closes a hole may make the library refuse what it used to
accept — markup the sanitizer now strips, a request a server handler now turns away — in any
release, and its changelog entry says so on its first line, with what to change.

What a default does is part of what its name does: copy off, compaction that runs by itself,
pictures held until a click. Changing one waits for a major, unless the security exception makes
it stricter. How a default looks is not frozen: a token's value, colours, spacing, English labels.

The lowest versions on the [support page](/reference/support/) — browsers, Node, each framework —
never rise in a patch. A minor raises one only to drop a runtime its vendor no longer supports
(Node 18 since April 2025), and says so on the first line of its changelog entry; any other raise
waits for a major.

Every `@aparte` package ships at the same version, and each one's peer range on another is that
version up to the next major: `@aparte/react` 1.2.0 asks for `@aparte/core` `>=1.2.0 <2.0.0`.

## The beta, 0.17 to 0.32

The beta froze the same names from **{frozen.frozenSince.version}** and kept them, with one
exception: 0.27.0 removed the package `@aparte/locale-fr` and its `fr` without a notice release
(the same `fr` is `@aparte/locales/fr`). It froze names, not what they did, so these changes of
behaviour or default reached code written against an earlier beta. Each is in the notes of the
release that shipped it; four of them came in a patch.

| Release | What changed | What to change |
| --- | --- | --- |
| 0.17.1 | `<aparte-suggestions empty-only>` shows while the conversation is empty, instead of hiding for good after the first send; `<aparte-chat data-empty>` is reflected without `center-empty`. | Add `[center-empty]` to a selector that relied on it. |
| 0.18.0 | `AparteClient`'s history carries the tool calls and their results (`toolCalls`, `role: 'tool'`). | A backend that serialises the history itself maps them, or drops them. |
| 0.19.0 | A `:root` rebrand now also applies in dark mode when `data-aparte-theme="dark"` is set. | Give dark a block of its own. |
| 0.19.3 | Derived tokens are worked out again on `[data-aparte-chat]`, so a value set on `:root` no longer reaches a React, Vue or Svelte chat. | List `[data-aparte-chat]` beside `aparte-chat`. |
| 0.19.3 | A button with no intent no longer reads `--aparte-btn-ink` where relative colour syntax exists. | Set `--aparte-on-neutral` instead. |
| 0.20.0 | `--aparte-message-content-text-user` and `-assistant` colour the words, not only the box. | Check that colour. |
| 0.21.0 | `<aparte-chat>` and `[data-aparte-chat]` paint `--aparte-bg` and `color`. | `background: none` to keep the page's own. |
| 0.22.0 | `createAgUiRunner` rejects a stream that does not follow AG-UI 1.0, and a `RUN_ERROR` no longer cuts the stream. | For TanStack AI, `relaxedRunFraming: true`. |
| 0.26.0 | `setupCompaction()` compacts automatically by default, deletes nothing, and refuses a model with no `contextWindow`. | `auto: false` to keep it manual; declare the window, or pass `contextWindow`. |
| 0.27.0 | `accept` on `<aparte-composer-add-attachment>` also applies to a file dropped, pasted, or picked through "All files". | — |
| 0.27.1 | Copy is off by default: `APARTE_DEFAULT_BUBBLE_ACTIONS.copy` is `false`. | `setBubbleActions({ copy: true })`. |

1.0.0 then removed what the beta had marked deprecated; the [changelog](/changelog/) lists each
name with its replacement.

## Changes of default in 1.0

| Release | What changed | What to change |
| --- | --- | --- |
| 1.0.0 | Pictures a model or a tool chose no longer load by themselves. `data:` and `blob:` pictures do; any other is shown as a link that names its host and loads on a click (a card shows one "Show images" button). A held picture is not fetched while a reply streams either, and every picture that loads goes with `referrerpolicy="no-referrer"`. | `aparteGlobalConfig.setImagePolicy(['self', 'https://cdn.example.com'])` for your own sources, or `['*']` for the earlier behaviour ([the policy](/guides/markdown/#pictures-a-reply-can-load)). |
